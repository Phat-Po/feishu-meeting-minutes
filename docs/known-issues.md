## 怎么查（先读这段）

- **不要整本读。** 先看下面「目录」找到模块，再按关键词或编号搜：
  `grep -rn "关键词" docs/known-issues.md docs/known-issues/`
- 每条都有编号（如 `KI-larkapi-001`）。交接文档、项目说明、提交记录里引用编号即可，一搜就中。
- 只保留结论：症状 → 根因 → 修法 → 以后注意。事故经过留在 git 历史或 handoff，不搬运。
- 每个模块内按时间倒序，最新在上。某模块条目太多时会搬到 `docs/known-issues/<代号>.md` 分册，目录会指过去。

## 复发规则（写条目前先读）

- 新增前先按关键词搜。同一个坑已有条目 → 在原条目加一行 `- **复发**：日期 + 一句话`，不另开新条。
- 复发（第 2 次起）→ 禁止沿用上次的修法，必须换思路找【根治】，别把绕行自动化。
- 每条修法标注【根治】或【绕行】；【绕行】要写明「还会复发、未根治」。

## [larkapi] 飞书接口


### 2026-11-21 | [larkapi] 时间戳跳转链接在手机上点了不跳

- **ID**：KI-larkapi-005
- **关键词**：?t=, 时间戳跳转, 手机, 移动端, 毫秒, 跳不过去
- **症状**：电脑上点章节时间能跳到录音对应位置，手机上打开录音但不定位。
- **根因**：飞书客户端对 `?t=<毫秒>` 的支持不完整，网上有第三方脚本专门补这个功能。
- **修法**：【绕行】链接照常生成（桌面可用）；手机端只能手动拖。还会复发，取决于飞书客户端版本。
- **以后注意**：别当 bug 去修。先确认桌面能不能跳：能跳就是客户端行为，两边都不能才是链接格式问题。


### 2026-11-21 | [larkapi] 覆盖文档后画板 ID 失效，内容写不进去

- **ID**：KI-larkapi-004
- **关键词**：overwrite, 覆盖, 画板token, new_blocks, 白板空白
- **症状**：覆盖文档内容后，再往旧画板 token 写，失败或内容丢失。
- **根因**：整篇覆盖会重建画板块，旧 token 作废。
- **修法**：【根治】覆盖后重新 `docs +fetch --doc-format xml` 读出新 token 再写。
- **以后注意**：建文档时从返回的 `new_blocks` 拿 token；只要做过覆盖，就必须重新取一次。


### 2026-11-21 | [larkapi] 录音列表一页只有 30 条，两次查询结果还可能不一样

- **ID**：KI-larkapi-003
- **关键词**：分页, page-size 30, page_token, 搜索结果不稳定, 漏数据, 查不到
- **症状**：补做历史录音时，前一次能查到的记录后一次查不到；超过 30 条的部分完全看不到。
- **根因**：接口一页上限 30 条，不翻页就静默截断；搜索索引本身也不稳定。
- **修法**：【根治】用 `page_token` + `has_more` 循环拉完；要处理指定 ID 时不要依赖搜索结果，直接按 ID 查详情。
- **以后注意**：任何「列表 → 逐条处理」的流程，都要假定列表可能漏；候选数为 0 时先怀疑分页。


### 2026-11-21 | [larkapi] 写画板时报「文件找不到」，文件明明存在

- **ID**：KI-larkapi-002
- **关键词**：@file, 相对路径, cwd, 文件找不到, no such file, whiteboard update
- **症状**：`whiteboard +update --source @b.json` 报 cannot read file。
- **根因**：`@文件` 是相对 **CLI 进程的工作目录**解析的，不是相对调用方脚本所在目录。
- **修法**：【根治】让命令在文件所在目录执行（subprocess 的 cwd）。
- **以后注意**：所有 `@文件` 参数都按「命令在哪跑」理解，不是「脚本在哪」。


### 2026-11-21 | [larkapi] 同一台机器装了两个版本的飞书命令行，报错和文档对不上

- **ID**：KI-larkapi-001
- **关键词**：lark-cli版本, 两个版本, which -a, 相对路径报错, 报错不一样
- **症状**：手动跑报「--output must be a relative path within the current directory」，定时任务里同样命令却正常。
- **根因**：系统目录里是旧版（1.0.87），npm 全局那份是新版（1.0.100）；旧版对输出目录校验更严，PATH 顺序决定用哪个。
- **修法**：【根治】`which -a lark-cli` 查重复并统一升级；脚本里用 `LARK_CLI=/绝对路径` 锁定版本。
- **以后注意**：报错信息跟文档里说的不一样 → 先查是不是装了多个版本。

## [render] 排版渲染


### 2026-11-21 | [render] 画板里的文字带尖括号，整篇文档解析失败

- **ID**：KI-render-002
- **关键词**：XML转义, 白板, 尖括号, 解析失败, 文档打不开
- **症状**：建文档直接失败，或文档能建但内容是空的。
- **根因**：白板内容嵌在 DocxXML 里，`<` 和 `&` 不转义会被当成标签。
- **修法**：【根治】所有进 XML 的文本统一过一遍转义，画板内容也不例外。
- **以后注意**：`<br/>` 这类要保留的标记，转义后解析时会还原，两种写法都能工作。


### 2026-11-21 | [render] 思维导图节点带括号引号，整张图渲染不出来

- **ID**：KI-render-001
- **关键词**：mermaid, 根节点, root, 标签清洗, 渲染失败, 空白画板
- **症状**：生成的画板一片空白，或只出来部分节点。
- **根因**：节点文字里的括号引号会破坏 Mermaid 语法；根节点 `root((...))` 被清洗函数误伤时整图失效。
- **修法**：【根治】清洗节点文字时保留根节点的 `root((...))` 结构，其余节点去掉括号、引号、冒号、竖线。
- **以后注意**：把模型文字塞进 DSL 或标记语言时，先分清哪些字符是语法的一部分。

## [model] 模型与提示词


### 2026-11-21 | [model] 生成的纪要看全是干巴巴的要点，没有一段完整的话

- **ID**：KI-model-002
- **关键词**：prompt, 字数限制, 全是bullet, 概括, 没有段落, digest
- **症状**：读者反馈「太简短」「怎么全是圆点」。
- **根因**：prompt 里每个字段都限成一句话（结论 30 字、要点 12 字），模型没有任何地方能写段落。
- **修法**：【根治】加 `digest` 字段，明确要求 2-3 句、60-120 字、写成段落不要用列表。
- **以后注意**：输出形态不满意时，先看 prompt 是不是把所有字段都限死了，别先怪模型。


### 2026-11-21 | [model] 模型返回了内容，但正文一个字都没有

- **ID**：KI-model-001
- **关键词**：max_tokens, thinking, stop_reason, 正文为空, 额度不够, 32000
- **症状**：日志显示 `blocks=['thinking']`、`stop=max_tokens`，正文为空。
- **根因**：推理模型先输出思考块，把输出额度吃光。
- **修法**：【根治】`AI_MAX_TOKENS` 提到 32000；脚本识别这个组合并给出提示。
- **以后注意**：加字段让输出变长时，要同步调额度，否则 JSON 被截断、解析失败。

## [deploy] 部署运行


### 2026-11-21 | [deploy] 加第二个飞书账号，把第一个账号的配置覆盖掉了

- **ID**：KI-deploy-002
- **关键词**：config init, --name, 覆盖, 多账号, 账号丢失, profile
- **症状**：给机器加第二个账号后，原先那个账号从 profile 列表里消失了。
- **根因**：`config init` 默认替换当前应用而不是追加；带 `--name` 才是追加。
- **修法**：【根治】加账号一律 `config init --app-id X --name Y --app-secret-stdin`。
- **以后注意**：多账号机器的初始化命令必须带 `--name`；执行前先备份配置文件。


### 2026-11-21 | [deploy] 定时任务里命令「找不到」，但手动跑正常

- **ID**：KI-deploy-001
- **关键词**：cron, PATH, command not found, 静默失败, 定时任务, 日志空白
- **症状**：crontab 里跑脚本，日志空白或报 command not found；手动跑没事。
- **根因**：cron 的 PATH 很短，npm 全局装的命令行不在里面。
- **修法**：【根治】启动脚本里显式 `export PATH="$HOME/.npm-global/bin:..."`。
- **以后注意**：任何定时任务都要假设 PATH 是空的。

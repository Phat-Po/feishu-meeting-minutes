# 踩过的坑和限制

这里记的都是真踩过的，不是想象出来的。

---

## 数据与隐私

**我的逐字稿会被存到哪？**

不存。脚本把逐字稿读进内存，拼进提示词发给模型，拿到纪要就完事。
唯一落盘的是 `state.json`，里面只有「处理过哪些笔记ID」，没有正文。

**除了模型服务商，还会发给谁？**

没有别人。飞书那边只是读取（它本来就是你的数据），写回去的只有一张卡片。

**用了官方 CLI，我的数据会不会经过第三方？**

`lark-cli` 是飞书官方维护的开源工具（MIT，`@larksuite/cli`），
请求直接打到飞书开放平台，中间没有第三方服务。

**团队能一起用吗？**

能，但要注意两件事：
1. 每个人的飞书登录态是独立的，各自跑各自的；
2. 脚本读的是**当前登录用户有权限看的会议**，不会越权读别人的会。

想做成团队共享的服务，得换成应用身份（`--as bot`）去做，那是另一套权限模型了。

## 为什么总是「0 场会议」

按可能性排序：

**1. 时间范围里真的没有会**
`--lookback 2` 只回看两天。先放大试试：

```bash
python3 meeting_summary.py --dry-run --lookback 30
```

**2. 会议没有生成笔记**
这是最常见的原因。飞书只有**开了会议笔记 / 纪要**的会才有逐字稿。
没有笔记的会，`vc +detail` 返回里没有 `note_id`，脚本只能跳过 —— 不是 bug。

验证一场会：

```bash
lark-cli vc +detail --as user --meeting-ids <会议ID> --json
```

看到 `"hint": "no minute file for this meeting"` 就是没笔记。

**3. 时区不对**
`vc +search` 的日期是本地时间算的。服务器时区如果是 UTC，
和你实际开会的时区差 8 小时，边界上的会就会漏。

```bash
date                     # 看看服务器认为现在是几点
sudo timedatectl set-timezone Asia/Shanghai    # Linux 改时区
```

## 为什么延迟 10 分钟

因为默认用轮询（每 10 分钟查一次有没有新纪要）。

飞书其实支持「纪要生成时推事件」，能做到秒级。但这个项目没用，原因很实在：

- 会议类事件在部分应用类型下**控制台里根本订不上**（我们实测两个应用都是这样）
- 事件订阅要么开公网回调，要么挂一个长连接常驻进程，比 cron 麻烦一个数量级
- 轮询的代价只是慢几分钟，对会后纪要完全够用

想验证你的应用能不能订：

```bash
lark-cli event consume minutes.minute.generated_v1 --as user --dry-run
```

看 `console_event_published` 是不是 `ok`。

## 模型相关的坑

### 返回了空正文 / 只有思考内容

有些推理模型会先吐一大段 thinking 块。如果 `max_tokens` 设小了，
token 全被思考吃光，正文返回空。

脚本的 `max_tokens` 是 `8000`，大部分模型够用。还不够就改大：

```python
"max_tokens": 8000,   # ← 改这里
```

脚本遇到「有返回但没正文」时会打印 `[AI 无正文] blocks=[...] stop=...`，
看到这个就是撞上了。

### 报错信息被当成纪要发出去了

**这是最容易踩的坑。** 如果用 `SUMMARY_CMD` 接外部命令：

- 命令失败但退出码是 0 → 脚本认为成功，把错误信息当纪要发给你
- 所以你的命令**失败时必须返回非 0**

脚本这边已经做了防护（退出码非 0 就跳过、不标记已处理、下次重试），
但防护只能靠退出码，命令自己不报错它也没辙。

### 模型开始编内容

提示词里那句「只写逐字稿里有的内容，不要推测」别删。
删了之后模型会补细节，补出来的东西读起来特别合理，但全是假的。

真要严谨，可以把提示词改成要求它「每条要点后面标注出自哪个说话人的哪句话」，
这样编没编一眼就看出来。

## 飞书接口的坑

### 明明有数据，却什么都解析不出来

`lark-cli` 的进度提示走的是 stderr，和 JSON 输出混在一起。
如果直接把 stdout + stderr 拼起来做 `json.loads()`，会报 `Extra data`。

脚本里的处理是：找到第一个 `{`，用 `json.JSONDecoder().raw_decode()` 只吃第一个完整对象，
后面多余的东西全部忽略。你自己写类似代码时照抄这个思路，别用 `find("{")` + `json.loads(整段)`。

### 凭证过期了

飞书的用户登录态（刷新令牌）会过期，一般几天到一个月。

过期后的表现是脚本报错、跳过、不发消息 —— 不会发错内容，但也收不到纪要。

```bash
lark-cli auth status --verify     # 检查并顺手续期
lark-cli auth login               # 真的过期了就重新登录
```

无人值守的机器要安排一个定期的 `auth status --verify`，让它自己续。

### 改了权限没生效

飞书要求**改完权限必须发布新版本**，老版本不会自动带上新权限。
发布完还要管理员审核通过（如果企业开了审核）。

## 重复与去重

**会不会同一场会发两次？**

不会。处理过的笔记 ID 记在 `state.json`，下次跳过。

**那我想重发怎么办？**

把那个 ID 从 `state.json` 的 `processed_notes` 里删掉，再跑一次。

**`--dry-run` 会写入记录吗？**

不会。空跑不写状态、不发消息，可以放心反复试。

## 成本

一场 1 小时的会，逐字稿大概 1-2 万字，按中文算大约 1-2 万 token。
用主流模型算，一场会几分钱到几毛钱，主要看你用哪个模型。

`MAX_CHARS = 45000` 是截断上限，超长的会只取前面部分。
如果你的会经常超过这个长度，改大它，但要接受对应的费用。

---

## 它做不到什么

- **会中实时纪要** —— 只做事后
- **没有笔记的会** —— 没逐字稿就没东西可总结
- **识别谁说了什么之外的语义**，比如语气、情绪、谁在敷衍 —— 别指望
- **替你保守会议秘密** —— 数据会发到你配的那个模型接口。公司有合规要求的话，
  用本地模型（`SUMMARY_CMD="ollama run ..."`）或者确认服务商的条款

## 还是卡住

按这个顺序排查，基本能定位：

```bash
# 1. 登录态和权限
lark-cli auth status --json
lark-cli auth check --scope vc:meeting.search:read

# 2. 能不能搜到会
lark-cli vc +search --as user --start 2026-01-01 --end 2026-12-31 --json

# 3. 这场会有没有笔记
lark-cli vc +detail --as user --meeting-ids <会议ID> --json

# 4. 逐字稿能不能拉下来
lark-cli note +detail --as user --note-id <笔记ID> --json

# 5. 模型通不通
echo "测试" | claude -p

# 6. 全套串一遍，不发消息
python3 meeting_summary.py --dry-run --lookback 7
```
